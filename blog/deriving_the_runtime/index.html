Deriving the runtime to get to #1 on $12 challenge

By Harsh Gupta · October 30, 2026

The post was published on 13th November, but I'm predating it to the date of the tweet to maintain the chronological record and proof of work

In the previous post, I described how Lean can be used for precisely and abstractly describing the domain you're working with, which I called domain driven development. This obviously reduces bugs. The less understood fact is that domain driven development can also make your code fast, like really fast.

Your hardware does not understand HTTP requests, or databases, or UI or any of these high-level concepts. The hardware understands very low level concepts like move this data from this pointer to this pointer, and do this computation on the data written at this pointer. So your high-level concepts need to be translated to the low-level. And this translation is done layer by layer. Each layer carrying it's own assumptions, and introducing its own inefficiencies.

Usually, your language will have something called a "runtime" which dynamically does this high-level to low-level translation. This runtime isn't always the fastest for your application because the runtime is written to support a lots of different kinds of applications. Languages like Rust and C, have a very thin and low-level runtime, so you get to control lots of low-level details making your code fast, but obviously it becomes hard to write low-level code directly. Languages like Python and Javascript have thick runtiimes and they handle a lot of stuff for you, but ofc making things slow.

In Lean, you can "derive the runtime", meaning, you can describe the high level behavior of your software, and generate the low-level code to implement that behavior, skipping the buggy and inefficient middle layers. Because Lean makes it easy to describe the global constriants and invariants of your software, you can have the low-level code carry over the high level invariants and only do what you really need to do.

I used this technique on the $12 server challenge and got to number one on the leaderboard, ahead of the C and Rust submissions. You can find the submission below.
